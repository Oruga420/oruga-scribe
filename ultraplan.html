What changed in rev 2

The subscription replaces the API key

Alejandro's call: the relay drives his already logged-in Claude Code instead of holding an Anthropic API key. It is his laptop and the SOPs are for him, so there is no reason to pay per token or to manage a secret. This is correct, and the research confirmed it works, but it moved the engineering in ways that were not obvious until the numbers came in.

Deleted outright: the relay .env for Anthropic, the dollar spend ledger, all explicit cache_control machinery, the anthropic-dangerous-direct-browser-access header, the host_permissions entry for api.anthropic.com, and the entire Chrome Web Store track (BYOK settings UI, privacy policy, Limited Use disclosure). The extension's only egress is now http://127.0.0.1:<port>.

Made mandatory: the relay. A browser extension cannot spawn a local process, so something has to host the CLI. It now holds no Anthropic secret at all, which is a strict improvement over rev 1.

Died on contact with evidence: the Agent SDK. It looked like the answer because it keeps one warm subprocess across turns. It is not worth it at v1: it bundles its own CLI (2.1.170 against the global 2.1.219) and the same model alias resolves to different actual models across the two, which is a silent-wrong-model hazard for 102 packages of dependency in exchange for roughly 1.5 seconds. Revisit only if the panel feels laggy in real use.

Changed in rev 2.3

Opus 4.8 is the SOP synthesis model

Alejandro's call, 2026-08-19. The default synthesis model moves from claude-sonnet-5 to claude-opus-4-8. The SOP is the deliverable of this tool, so it gets the Opus-tier pass by default instead of behind a checkbox. The model ID carries no date suffix, and the same string works on Vertex, where current generation models use the bare first party ID with no provider prefix.

Narration deliberately stays on claude-haiku-4-5. It fires every 6 to 8 seconds against a live panel and its output is disposable by design, never the SOP source. An Opus-tier call on that path buys nothing and costs the panel its responsiveness. If you want narration on Opus 4.8 too, say so and it is a one-line change.

Worth knowing: Opus 4.8 is active but superseded. claude-opus-5 is the current Opus at the identical $5 / $25 per MTok, the same 1M context and the same feature set. Alejandro was told this and chose 4.8, so it stands.

Found while making the change: the opt-in upgrade checkbox was never built. relay/server.js reads body.upgradeModel and relay/claude.js branches on it, but panel.js posts only { session } and no UI element sets the flag, so it has always been falsy. Consequence: every SOP ever synthesized by this tool ran on the default model, and MODELS.synthesizeUpgrade is unreachable except by hand-crafting a request. After rev 2.3 that default is Opus 4.8, which is what was wanted anyway. Two clean ways out, Alejandro's pick: build the toggle in the panel, or delete the slot and the branch. Leaving a live branch no caller can reach is exactly the shape of the nine bugs that returned success while broken.

Section 01

Executive summary

Build a Manifest V3 Chrome extension plus a localhost relay. The extension captures interactions from a content script, screenshots the viewport through a single throttled scheduler, and holds all session state in a side panel document. The relay spawns claude -p per call, one profile for live narration on Haiku 4.5 and one for end-of-session synthesis, and enforces the redaction gate and the quota guards. Live narration covers debounced groups of one to three settled steps. The SOP is one call over a list you pruned by hand, rendered to an editorial HTML page plus Markdown, zipped through chrome.downloads.

Three platform facts from rev 1 still drive the architecture. The side panel owns the session, not the service worker, because the worker dies after 30 seconds idle and an open panel does not keep it alive. Declare host_permissions: ["<all_urls>"] instead of activeTab, because activeTab is silently revoked on cross-origin navigation. Never accumulate screenshots in context.

Rev 2 adds a fourth, and it is the single highest-leverage line in the whole build: set MAX_THINKING_TOKENS=0 in the child environment on the narration path. Extended thinking is on by default in this install, it is not disabled by --safe-mode, not by effortLevel in settings.json, and only weakly by --effort low. On a pure transcription task it was burning about 2.5 seconds and 540 of 649 output tokens per call. Turning it off took a narration call from 10.8 seconds to 3.3 seconds and time to first visible word from 10.4 seconds to 1.9 seconds. Nothing else in this plan comes close to that.

Section 03

Two dangerous silent failures

Both return exit code 0, subtype: success, is_error: false, and empty stderr. For a tool whose entire output is a document someone will follow, silent corruption is worse than a crash.

1. Tall images are silently mangled

A 1280x5000 capture came back reading perfectly authoritative and with every single field corrupted: FAULT-ZIOT II for FAULT-Z30T1I, Reticulum POKY for Reticulate PXWY, zeptylene for zephyrine, Rushdown for thaddeus, inc CRUD-GCHT4 for rev CWQ-QQHH4. Token math proves the mechanism: the billed 878 tokens matches a 401x1568 downscale, not the 1280x5000 that was sent. The long edge gets squeezed to about 1568 px and the text turns to mush that the model then confidently reads wrong.

Guard, non-negotiable: in the relay, before encoding, reject or tile anything past roughly 2:1 aspect, hard cap the long edge at 1568 px, and target 1024x640 WebP. Viewport captures are naturally about 16:10 so this mostly bites if full-page capture is ever added.

2. Corrupt base64 fails without failing

Truncating the base64 in half gave exit 0, success, no error, empty stderr. The only evidence was inside the assistant text: API Error: an image in the conversation could not be processed and was removed.

Guard: string match that phrase in the response, and plant a sentinel instruction so a missing image makes the model emit NO-IMAGE-RECEIVED. Both halves verified working. Never trust the exit code on an image call.

Section 04

How a recorded step actually works

Unchanged from rev 1, and still the hardest bug in this class of tool. Capture after the click and the frame shows the destination page attributed to the click that left it. Capture before and the menu is not open yet.

  • Rolling frame. Capture the viewport at most every 1000 ms while idle and hold it as lastFrame. A free before-image that costs no quota at click time.
  • On pointerdown (capture phase, passive), synchronously serialize the target descriptor: tag, role, accessible name, bounding rect, nearest heading or landmark, frame URL, page title. By click the node is often already gone.
  • On click, start a settle race. MutationObserver quiet for 400 ms with a 2500 ms ceiling, versus webNavigation.onCommitted, versus rAF plus requestIdleCallback. First to fire wins.
  • If navigation won, attribute the step to the old page using the URL and title from pointerdown, then capture the new page on first paint and label it "result of step N". Never as the next step's before-image.
  • If settle won, capture the after-frame.
  • Diff. Downscale both to 32x32 grayscale and sum the absolute difference. Below threshold with no mutations, mark low_signal as a candidate for auto-prune.
  • Persist. JPEG q80 out of captureVisibleTab, transcode to WebP q80 at 1024x640 for the model and 1600 px max for the document, write to IndexedDB keyed by step id.
  • One 550 ms-gap scheduler for every capture. A quota miss degrades the step to frame:reused. It never loses the step.

Design answers, carried forward

Live narration in groups, not per click. You asked for narration while we work, and live output is the only early warning that capture has broken. But at step 2 the model cannot know that "clicked Settings" was the opening move of "rotate the Slack token". So narration covers debounced groups of one to three settled steps and is treated as disposable. The SOP is always re-synthesized at the end over the pruned list.

Debounce floor is 6 to 8 seconds, revised up from 5. With a 3.3 s text call and a 4.7 s image call, 6 s is a workable duty cycle under single flight and 8 s is comfortable. Never two concurrent spawns: while a call is in flight, merge newly arriving steps into the next payload instead of queueing another process.

The goal field is mandatory and blocking. One field doing four jobs: highest-value token for narration quality, the SOP title, the origin allowlist scope, and the company tag that keeps Promise, Sesh, VCC and Price Point out of each other's output. Typed notes on a hotkey per step, yes. Voice memos, no.

Section 05

The two spawn profiles

Verified against claude 2.1.219 on Windows. Both spawn the native executable with an args array and shell:false, with all user content arriving over stdin.

# narration, fires every 6 to 8 s, images inline as base64 env: MAX_THINKING_TOKENS=0, CLAUDE_CONFIG_DIR=relay/.claude-home claude -p --input-format stream-json --output-format stream-json --verbose --include-partial-messages --model claude-haiku-4-5 --permission-mode dontAsk --tools= --strict-mcp-config --mcp-config "{\"mcpServers\":{}}" --setting-sources= --disable-slash-commands --system-prompt-file prompts/narrate-system.txt < one JSONL line: text blocks plus optional image block # synthesis, once per session, thinking left ON env: CLAUDE_CONFIG_DIR=relay/.claude-home claude -p --output-format json --verbose --model claude-opus-4-8 # rev 2.3, Alejandro's call. Always this: see the dead upgrade slot below --permission-mode dontAsk --tools= --strict-mcp-config --setting-sources= --disable-slash-commands --system-prompt-file prompts/sop-system.txt --max-budget-usd 1.00 < the pruned step log

Flag traps, all verified the hard way

  • --verbose is required with -p plus stream-json, or the process exits immediately with an error. Guaranteed half hour lost if undocumented.
  • --bare is disqualified. It looks like the perfect isolation flag but auth becomes strictly ANTHROPIC_API_KEY or apiKeyHelper, and OAuth and the keychain are never read. On a subscription it hard-fails with "Not logged in". Assemble isolation from the granular flags instead.
  • --safe-mode does not override model: opus[1m] from settings.json. A run that looked fully isolated was silently executing on Opus 5 with a 1M context. Always pass --model explicitly.
  • No Read tool. Images go inline as base64 content blocks, which needs no filesystem and no tools. Enabling Read costs about 6.0k input tokens of scaffolding plus two extra turns, and it would turn the child's cwd into a Claude Code project that writes session JSONL and auto-memory outside the redaction gate.
  • Windows spawn hazard. claude on PATH is a shell script with .cmd and .ps1 siblings; shell:true makes cmd.exe concatenate args unescaped and silently mutilate multiline prompts. Short static argv, content via stdin, persona via --system-prompt-file, empty-valued flags as single tokens. Kill orphans with taskkill /T /F.
  • --system-prompt-file is mandatory on both paths and is not in the top-level help. Without it the CLI loads its own agent persona: 6,316 input tokens, 486 output tokens and agent chatter, against 149 input, 8 output and the correct sentence. Do not conclude from a quick --help read that the flag does not exist.
  • Read usage from the JSON result event, which also carries ttft_ms. total_cost_usd is synthetic on a subscription. The real quota signal is rate_limit_event.

The guard that matters is model routing on synthesis, not batching narration harder. Narration is about $0.03 of synthetic equivalent per session, so coarsening the debounce to save quota is not supported by the numbers. The one synthesis call is where the bite is, and as of rev 2.3 that call runs on Opus 4.8 by Alejandro's call: the SOP is the deliverable, so it gets the Opus-tier pass rather than an opt-in checkbox.

Provenance of the $0.73. Same measured token counts as rev 2.2, repriced from Sonnet 5 list ($3 / $15 per MTok) to Opus 4.8 list ($5 / $25). No new measurement was taken, so treat it as arithmetic on a measured base, not a fresh reading. Opus 5 sits at the same $5 / $25, so the opt-in upgrade is now a generation change rather than a cost decision.

Degrade, do not die. When rate_limit_event comes back with status other than allowed, the relay stops calling but the extension keeps capturing and screenshotting locally, surfaces resetsAt in the panel, and lets the SOP be synthesized after the window resets. Losing narration should never lose the recording.

Warn about interactive sessions, gate only synthesis. Narration is cheap enough to just run. Before the synthesis call, if an interactive Claude Code session is busy, offer run now or queue until idle, and default to queue.
